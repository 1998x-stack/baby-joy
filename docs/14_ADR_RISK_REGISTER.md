# 14｜Architecture Decision Records & Risk Register

## ADR-001｜只做微信原生小程序
**Accepted for MVP**。用户家庭场景高度依赖微信生态，原生小程序可简化照片权限/视频相册保存与试用路径。牺牲首版跨平台，但避免同步维护 Web/H5 端。未来可提取 API 契约重用。

## ADR-002｜统一 API 受理，GPU 与 API 解耦
**Accepted**。小程序只认识后端 HTTPS API；API 轻请求 + 长任务服务端调度。单机可 Docker Compose；GPU worker 可拆独立私网节点，避免 API 阻塞。禁止在微信客户端保留 AI 推理密钥。

## ADR-003｜优先 EchoMimicV3-Flash，保留多模型对照
**Provisional / Gate G1**。优点：易搭建与潜在低显存；风险：婴儿脸部与时序稳定性未知。只有 Phase 0 实测及许可审批通过后才能固化为生产模型。InfiniteTalk 与 Wan2.2-S2V 作为质量/成本对照。

## ADR-004｜Postgres 真相 + Transactional Outbox + Redis/Celery
**Accepted**。并发任务低时比复杂工作流平台轻量；必要的 outbox + lease + fencing 提供重复投递与宕机恢复。未来任务非常复杂才考虑 Temporal，不做多套队列并存。

## ADR-005｜MVP 上传走后端 API
**Accepted**。微信 `wx.uploadFile` -> API 文件验证/授权 -> 私有存储，统一控制入口。优点是合规与链路简单；缺点是 API 承载上行流量。达到上传吞吐阈值后才研究可授权直传对象存储，但必须继续由 API 颁发一次性授权并符合小程序合法域名限制。

## ADR-006｜祖辈先作为接收者
**Accepted for MVP**。爷爷奶奶拿到照片不代表拥有法定监护权；第一版由父母或监护人发起。未来家庭协作需要可撤销的监护人授权模型。

## ADR-007｜私有下载，不做公开作品流
**Accepted**。预览/下载须按 user_id 授权；视频保存到系统相册由用户主动操作。私密分享链接的传播风险复杂，P1 再设计。

## ADR-008｜先评测质量，不从零训练
**Accepted**。Baby-Aware Motion Control 首先是轻量参数/质检/动作约束研究。只有明确高质量训练数据合法权利、隐私治理、失败模式和 ROI 后才启动模型微调。

## 待决事项
- 中国大陆实际运营主体、服务器区域、域名/备案和微信审核类目。
- 监护人授权的可核验要求、适用监管备案边界。
- 合法商用儿童 TTS 音色来源。
- 单机 GPU 具体型号与可承受峰值价格；是否完全私有部署。
- 用户满意度和失败补偿策略的真实产品实验。
不得未经证据将其改写为既定事实。
